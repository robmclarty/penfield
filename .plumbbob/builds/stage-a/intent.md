# Stage A: auto by rules, any client

**Phase** (your own bookkeeping while framing): frame
**Size:** medium
**Scope:** penfield

*Source:* `docs/specs/first-spec/penfield_first_spec.md` §8 Stage A (spec steps 2–20), with the build guidance of `docs/specs/first-spec/playbook.md` §2 and the repo's `AGENTS.md` and `rules/`. ## Frame

- **Problem:** Every tool in the house that wants a model (Zed, fascicle flows, volley, night-shift, runciter, shinbun, nurselog, lodestar) carries its own idea of which model lives where. Nothing knows what is resident on searle right now, nothing shares a policy about privacy, speed, quality and cost, and nothing decides when a prompt is beyond the local models and should go to Claude. Rob makes that call by hand on every prompt, or not at all.
- **Smallest thing that solves it:** One service on plato with one settings file (`penfield.yaml`). It keeps a catalogue of nodes and models, probes them, and answers requests in the OpenAI wire format (Anthropic is Stage B). A request naming a real model is forwarded to the node that has it. A request naming `auto`, an alias or a profile is routed by a cheap ladder of rules to a profile, placed on a resident, healthy, free model, and forwarded unchanged. When the answer is "this needs Claude", the gateway says so and the requester's own client runs Claude under its own login. Every decision is logged.
- **Done looks like:** Proved by the gate, with the fake Ollama and fake OpenAI servers: `pnpm check` green through spec step 20, every step's done-when below met by tests. Proved live, by Rob at the range stops: from this laptop, with `deploy/penfield.example.yaml` naming searle and claude, `curl` to `/v1/chat/completions` with `model: auto` streams an answer from the right model on searle; `model: qwen3.8:27b-mlx` forwards verbatim; `/v1/embeddings` with `auto` lands on an embedding model; `/v1/models` lists `auto`, the aliases and the catalogue; Zed's native agent uses the gateway as an `openai_compatible` provider and switches models in its picker; a busy or down searle degrades to the next candidate or fails fast with a clear error; `/decisions` shows every request with its rung, target and timings; Uptime Kuma sees `/healthz` on plato; the CHANGELOG has 0.1.0 (from `/version minor`, after `/plumbbob:finish`).
- **Explicitly NOT doing:** Translating between wire formats. Holding or forwarding any Claude subscription credential. Running a model on plato. Anthropic `/v1/messages`, `/route` for Anthropic or bare bodies, admin endpoints, the ACP agent, the systemd watchdog (Stage B). The embedding and classifier rungs, exemplars, `keep_prompts` replay (Stage C). A persistent queue, the `anthropic_api` leg and `on_claude_for_proxy: api_key`, `recover.command`, `/metrics`, budgets (Stage D). Voice and more nodes (Stage E). Team features. A `penfield catalogue` CLI (no §8 step names it; `/catalogue` and the UI cover it). Any LLM call in the placement step. Writing the CHANGELOG by hand.

## Architecture sketch

```text
clients                         plato: penfield                            nodes
Zed native agent  ─OpenAI─┐     ┌──────────┐  ┌─────────┐  ┌─────────┐   searle (Ollama, MLX)
fascicle flows    ─OpenAI─┼────▶│  wire    │→ │ router  │→ │ place   │→  openrouter (cloud, policy-gated, off)
n8n, curl, agents ─OpenAI─┤     │ auth,    │  │ ladder  │  │ leases, │   claude_decision (never executed here)
                          │     │ proxy,   │  │ rungs   │  │ pins,   │
                          │     │ SSE pipe │  │         │  │ breaker │
                          │     └────┬─────┘  └────┬────┘  └────┬────┘
                          │     ┌────▼─────────────▼────────────▼────┐
                          │     │ catalogue ◀─ prober ◀─ nodes' /api │
                          │     │ decision log (SQLite) · leases      │
                          └────▶│ UI page · /healthz · /catalogue     │
                                └─────────────────────────────────────┘
```

Request path for `auto`: **wire** authenticates the caller and parses just enough of the body (endpoint, model, message text, tools, attachments, rough token count, hints) → **router** runs the ladder and names a profile with a confidence → **placement** ranks the profile's candidates against the catalogue and the lease table and picks one (or returns a `claude_decision`, or degrades) → **wire** rewrites `model`, forwards the original body to the node's matching endpoint, pipes the stream back, and releases the lease at the last byte → **log** records the decision and the outcome.

Module seams (spec §7, adjusted to the repo's rules): `packages/penfield/src/{config,catalogue,probe,place,route,wire,log,ui}/` each with an `index.ts` barrel, `src/cli.ts` the bin, `src/index.ts` the package barrel. Contracts the reviewer holds steady: `snapshot(): Catalogue` (pure data; nothing else reads a node), `route(input, catalogue, policy)` (pure; model rungs injected, absent in Stage A), `place(profile, input, catalogue, leases, policy): Decision` (pure over a lease snapshot; acquire is a separate call so `/route` never acquires), `proxy(decision, request, reply, lease)` (the only code touching upstream sockets), `release(lease_id, outcome)` (the single release path, idempotent), `log.decision`, `log.outcome`, `log.incident` (append-only).

## Decisions

The spec's D1–D25 are settled (re-open one in a spike, not in a change); D26 onward are this plan's calls.

- <a id="d1"></a>**D1 (one-settings-file)**: One service, one settings file, no hard-coded universe: every node, model, profile, policy and caller comes from `penfield.yaml`, *because* portability was the first requirement.
- <a id="d2"></a>**D2 (proxy-not-translate)**: Forward in the format the request arrived in, to a node that speaks it, rewriting `model` and nothing else, *because* Ollama, llama.cpp, LM Studio and oMLX speak both formats natively and translation is where gateways grow fat.
- <a id="d3"></a>**D3 (node-fastify-zod-sqlite)**: TypeScript on Node 24, Fastify, zod, SQLite, functional style, checkride the gate, plumbbob the loop, *because* that is the stack every tool in the folder shares.
- <a id="d4"></a>**D4 (no-engine-hot-path)**: No fascicle in the hot path; proxying is raw `fetch` and stream piping (fascicle arrives with the classifier rung, the API-key leg and the ACP agent, none in Stage A), *because* a proxy's job is bytes.
- <a id="d5"></a>**D5 (runs-on-plato)**: Container or systemd on plato, config in git, state in one SQLite file under `/var/lib/penfield`, *because* plato is the control plane, on the UPS, and auditing AI use is its mission.
- <a id="d6"></a>**D6 (explicit-wins)**: A concrete model id is forwarded to the node that has it, no ladder, placement choosing only among nodes with that exact model, *because* override must be absolute.
- <a id="d7"></a>**D7 (cheapest-rung-first)**: The ladder is `explicit` → `alias` → `shape` → `rule` → `embedding` → `classifier` → `default`, stopping at the first rung whose confidence clears the threshold; Stage A ships the first four and `default`, *because* most traffic is decidable from the request shape at zero cost.
- <a id="d8"></a>**D8 (profiles-route-models-place)**: Profiles (`embed`, `classify`, `extract`, `summarize`, `chat`, `code-light`, `code-heavy`, `reason`) are the unit of routing and models the unit of placement, each profile listing ranked candidates in config, *because* a profile is stable across machines and models are not.
- <a id="d9"></a>**D9 (decision-carries-alternatives)**: A `Decision` carries ranked alternatives, its rung, its reasons and a confidence, and `/route` returns it whole, *because* "choice one is busy, use choice two" is then a filter and the log becomes the eval set.
- <a id="d10"></a>**D10 (privacy-quality-speed-cost)**: Policy precedence is privacy, then quality above the threshold, then speed, then cost; privacy classes `local`, `lan`, `cloud`; a caller's `max_privacy` caps it, default `lan`, *because* Rob said so and cost only exists on the cloud leg.
- <a id="d11"></a>**D11 (classifier-two-questions)**: The Stage C classifier answers only "local or Claude" and "which tier" for free-form chat, *because* everything else is decidable without a model in the path.
- <a id="d12"></a>**D12 (placement-reads-live-state)**: Placement reads residency, health, breaker state, free slots and pins, taking the first candidate that is resident, healthy and free, else the first healthy and loadable if `cold_load` allows, else the busy policy, *because* on a 48 GB Mac, available means resident.
- <a id="d13"></a>**D13 (leases)**: Every forwarded request holds a lease on `(node, model)` from dispatch to the last byte or disconnect, slot counts per model from config with a node default, *because* Ollama queues blindly and cannot see memory thrash coming.
- <a id="d14"></a>**D14 (pinning)**: A model `pinned` on a node is never evicted by a load the gateway triggers; placement routes elsewhere, degrades or waits, *because* one person's 27B must not unload the 35B someone else is mid-stream on.
- <a id="d15"></a>**D15 (busy-policy)**: Busy policy per caller and profile is `degrade` (default interactive) or `wait` with a deadline (default batch); Stage A's `wait` is one in-memory FIFO per `(node, model)`, no fairness, *because* the lease table is the seam Stage D's queue plugs into.
- <a id="d16"></a>**D16 (hung-work-recovered)**: Client-gone, stall, deadline, orphaned lease, unresponsive node and wedged model are each detected and recovered in the escalating steps of spec §6, every step an `incidents` row, *because* a lease never released is a slot never free.
- <a id="d17"></a>**D17 (no-subscription-credential)**: The gateway never holds, sees or forwards a Claude subscription credential; a `claude_decision` target is a decision the requester's client executes under its own login, *because* Anthropic's terms forbid intermediating subscription credentials.
- <a id="d18"></a>**D18 (optional-api-key-leg)**: An `anthropic_api` target with an API key executes server-side, budgeted, off by default (Stage D), *because* unattended LAN agents need a permitted path.
- <a id="d19"></a>**D19 (claude-for-proxy)**: A proxy endpoint that resolves to `claude_decision` applies the caller's `on_claude_for_proxy`: `hint` (a short assistant message naming model and effort, default), `downgrade` (best local candidate plus `x-penfield-downgraded`) or `api_key` (Stage D), *because* curl and Zed's native agent cannot act on a decision and answering locally in silence would hide the routing.
- <a id="d20"></a>**D20 (acp-delegates-claude)**: The Stage B ACP agent delegates its Claude branch to `claude-agent-acp` as an ACP client, *because* that is what Zed's Claude thread has today.
- <a id="d21"></a>**D21 (every-request-has-caller)**: Every request carries a caller (bearer token → name, policy, priority); no anonymous requests; LAN bind only, *because* multiplayer, budgets and fairness hang off identity and Ollama has no auth.
- <a id="d22"></a>**D22 (log-decisions-not-prompts)**: Log decisions, not prompts, by default; per-caller `keep_prompts: true` keeps prompt text; model output is never stored, *because* that is nurselog's doctrine and plato's audit role wants decisions.
- <a id="d23"></a>**D23 (neutral-log-schema)**: The decision log is in the gateway's own schema, never a node's, *because* the log must outlive any vendor and is the regression suite.
- <a id="d24"></a>**D24 (one-yaml-entry-per-node)**: A node is one YAML entry; models are discovered (`/api/tags` and `/api/ps` for Ollama, `/v1/models` for OpenAI-compatible, hand-listed otherwise) and metadata overlaid by glob, *because* adding a node must take a minute.
- <a id="d25"></a>**D25 (health-where-plato-looks)**: `/healthz` for Uptime Kuma, the UI page, a metrics line later, *because* Grafana stays off the roadmap.
- <a id="d26"></a>**D26 (barrel-per-module)**: Each folder module has an `index.ts` of re-exports only, siblings import through `../<module>/index.js`, `src/index.ts` stays the package barrel re-exporting the seam contracts as they land, and `src/cli.ts` is the `bin`; both are fallow entries, *because* the `no-deep-sibling-import`, `no-logic-in-barrel` and fallow checks say so.
- <a id="d27"></a>**D27 (deps-when-first-imported)**: `zod` and `yaml` arrive with spec step 2, `fastify` with spec step 4, each exact-pinned in the step that first imports it; no glob library: `*` is the only wildcard in `models:` keys and is matched by a regex built from the key, *because* fallow fails an unused dependency and every example glob uses only `*`.
- <a id="d28"></a>**D28 (example-config-first)**: `deploy/penfield.example.yaml`, the playbook §4 house config naming searle at `192.168.1.90`, lands with spec step 2 as the schema's first real input; spec step 18 adds the rest of `deploy/`, *because* the live checks from spec step 8 on need a real config to run with.
- <a id="d29"></a>**D29 (laptop-overrides)**: `serve` reads `--config <path>` or `PENFIELD_CONFIG`, and `--listen`, `--state-dir` and `--tokens-file` override the file; a loopback bind is allowed (stricter than LAN); the laptop's live command is `PENFIELD_CONFIG=deploy/penfield.example.yaml node packages/penfield/dist/cli.js serve --listen 127.0.0.1:7777 --state-dir /tmp/penfield --tokens-file ~/.config/penfield/tokens`, *because* the example's listen address, state dir and tokens path are plato's.
- <a id="d30"></a>**D30 (auth-arrives-with-models)**: `wire/auth.ts` (tokens file → caller; no token or an unknown one → 401) lands with spec step 8, and spec step 13 (request ids, the error envelope, the fail-closed 403) builds before spec step 12, *because* `/v1/models` filters by the caller's policy and `/route` needs the envelope and `x-penfield-request`.
- <a id="d31"></a>**D31 (log-carries-route-input)**: Beyond spec §5.5, a `decisions` row carries `input` (the `RouteInput` as JSON without `text` and `system_text`), `prompt` (those two as JSON, only under `keep_prompts`) and `upstream_prompt_tokens`, *because* `replay` re-runs the ladder from the row and [Q4 (token-estimate-quality)](#q4) compares the estimate with the node's count.
- <a id="d32"></a>**D32 (ui-page-static-unauthenticated)**: `GET /` serves markup only, unauthenticated like `/healthz`; the page asks for a token once, keeps it in `localStorage` and sends it as a bearer on every fetch to the data endpoints, *because* a browser cannot set a bearer header on navigation and the data stays behind [C5 (lan-and-tokens)](#c5).
- <a id="d33"></a>**D33 (fakes-prove-live-steps)**: Spec steps 8, 12, 15, 16 and 18 have done-whens the fake servers prove; the check against searle, Zed or plato is Rob's call at the range's stop and is recorded in the build log, *because* the gate runs without the LAN.
- <a id="d34"></a>**D34 (timers-injectable)**: Prober, breaker, leases and proxy take their clock and timers as arguments, so tests run on a fake clock, *because* the gate cannot wait 30 s for a half-open probe.
- <a id="d35"></a>**D35 (shape-is-the-endpoint)**: The `shape` rung answers from the endpoint alone (`embeddings` → `embed`, audio → `stt`/`tts`) at confidence 1.0; `rule` walks `router.rules` in order (`$hint` and `chat: true` included) at 1.0; `default` answers `chat` at 0.5 and is taken only because nothing sits below it in Stage A, *because* the spec names the rungs but not where shape ends and rules begin.
- <a id="d36"></a>**D36 (replay-reads-the-db)**: `penfield replay` and `penfield decisions` open `penfield.db` directly and need no running server, *because* they are offline reads and the service may be down when a rule is being edited.
- <a id="d37"></a>**D37 (stops-are-plumbbob-items)**: The spec's five ranges become eight `## Build ranges` items, because plumbbob can pause mid-range only as a bare `/plumbbob:build N` item: the playbook's two pauses (spec steps 11 and 14) split ranges 3 and 4, and the spec's stops after 4, 8, 12, 16 and 20 are kept, *because* a pause the plan reserves has to be a stop the run honours.
- <a id="d38"></a>**D38 (models-list-filters-auto)**: A caller's `models:` allow-list filters the candidates of an `auto`, alias or profile request (a skipped candidate carries the reason) and refuses an explicit model outside it with 403, *because* `nurselog` must be able to say `auto` and still only ever land on its two models, while [C11 (fail-closed)](#c11) wants a named model it may not use refused, not substituted.
- <a id="d39"></a>**D39 (node-sqlite)**: `log/db.ts` uses `node:sqlite` (`DatabaseSync`), the only module that touches the driver, *because* it is built into Node 24 with no native build, no `allowBuilds` entry and no toolchain in the image, and a swap to `better-sqlite3` is then one file.
- <a id="d40"></a>**D40 (yaml-line-counter)**: The loader parses with the `yaml` package's `parseDocument` and a `LineCounter`, validates `doc.toJS()` with zod, maps each issue's path to its node's offset for a line and column (a missing key reports its parent's line), and prints `penfield.yaml:42:7 aliases.auto.ladder: <message>`, *because* zod carries paths, not positions, and a line is what an editor jumps to.
- <a id="d41"></a>**D41 (candidate-two-tiers)**: At load, only static facts fail (an unknown key, an alias to a missing profile, a candidate naming a node that does not exist or a model a hand-listed node lacks, a pinned model a hand-listed node lacks); after each discovery, a candidate no node has is a `candidate_missing` incident shown in the UI and never a boot failure, *because* plato must boot while searle is down or a model is being re-pulled, which is the state D16 recovers from.
- <a id="d42"></a>**D42 (refuse-claude-env-names)**: A node whose `api_key_env` names a variable starting with `CLAUDE_` fails at load, *because* the `no-subscription-login` rule sees only names written in code, and without this check the file could point the gateway at a subscription credential, which [C2 (no-subscription-credential)](#c2) forbids.
- <a id="d43"></a>**D43 (decision-policy-column)**: A `decisions` row also carries `policy`, the Decision's policy object as JSON. Step 12 adds the column in `log/db.ts` with `user_version` 2, *because* spec §5.5 has no column for it and step 12's row has to equal the response.
- <a id="d44"></a>**D44 (memory-fit-cold-load)**: A cold load goes ahead only when the model fits in its node's `memory_gb` beside the resident models that are pinned or leased, its weights counted from discovery's `size_bytes` plus a KV allowance step 10 sets; otherwise placement degrades or waits by the busy policy, *because* step 10 must refuse a load that would evict a pinned model, and only a memory fit can tell when one would (range 2's stop, P8).
- <a id="d45"></a>**D45 (readiness-acts-on-a-hang)**: A readiness ping that times out is a hang, and only a hang takes `unload_on_hang`; a refused connection or a 5xx counts toward the model's breaker without an unload; a 4xx (an embedding model's `does not support generate`) means the runner answered and counts as nothing, *because* spec §6 recovers a model that hangs, and on searle a 400 made the prober unload `nomic-embed-text` and open its breaker (range 2's stop, P9).
- <a id="d46"></a>**D46 (ollama-picks-the-evictee)**: While a pinned model is resident on a node, a cold load there goes ahead only when it needs no eviction at all: it fits in `memory_gb` beside every resident model, and the resident count stays under the node's `max_loaded` when the node sets one (the `OLLAMA_MAX_LOADED_MODELS` it runs with). With no pinned model resident, D44's fit holds, and a load at the cap goes ahead only when a resident model is idle, which Ollama unloads first. A model holding a lease counts as resident, and a refusal names the fit or the cap and the pin, then degrades or waits by the busy policy, *because* Ollama, not penfield, picks the model it unloads and knows nothing of pins, so [D14 (pinning)](#d14) holds only if the gateway never triggers an eviction Ollama could aim at the pin, and [C1 (proxy-dont-translate)](#c1) and spec §6 leave `keep_alive` as the client sent it (range 4's harvest, P16).
- <a id="d47"></a>**D47 (reaper-grace)**: The reaper takes an active lease only once it is 30 s past its `deadline_at`; at the deadline itself the proxy's own timer aborts and releases with `deadline`, *because* both fire at `deadline_at`, and a reaper tick that lands first logs `orphaned` and writes a false incident for a request that simply ran out of time, while the reaper stays the backstop for a holder that died (range 4's harvest, P18).

## Constraints

The spec's C1–C11, as the reviewer checks them; C12 onward come from `AGENTS.md`, `rules/` and the toolchain.

- <a id="c1"></a>**C1 (proxy-dont-translate)**: No wire-format translation; a node lacking the incoming format is a refused candidate with the reason in the decision.
- <a id="c2"></a>**C2 (no-subscription-credential)**: No Claude OAuth token, its env name, session or credentials file is read, stored, forwarded or logged anywhere in the codebase; the `no-subscription-login` rule blocks the names, and a test asserts the proxy strips inbound `Authorization`-class headers it did not set.
- <a id="c3"></a>**C3 (no-model-call-in-placement)**: Placement never calls a model; the classifier rung (Stage C) is the only model call in the routing path.
- <a id="c4"></a>**C4 (stream-never-buffer)**: Request bodies are read once and forwarded; response bodies are piped, never buffered whole; memory stays flat under a 100 k-token response.
- <a id="c5"></a>**C5 (lan-and-tokens)**: Bind to the LAN interface only (loopback allowed, `0.0.0.0` refused without `--allow-any-interface`); every endpoint except `/healthz` and the static `/` page requires a caller token; tokens come from env or a file outside the repo, never `penfield.yaml`.
- <a id="c6"></a>**C6 (functional-typescript)**: No `class`, `this`, `extends`, decorators or ambient singletons; config is parsed once with zod and passed down.
- <a id="c7"></a>**C7 (check-is-done)**: `pnpm check` exit 0 is the definition of done; no `any`, no `@ts-ignore`, no suppression comments, no baseline additions.
- <a id="c8"></a>**C8 (one-sqlite-file)**: One SQLite file holds log, leases and incidents; no Postgres, Redis or second daemon.
- <a id="c9"></a>**C9 (footprint-250mb)**: Under 250 MB resident on plato with the UI open and ten concurrent streams.
- <a id="c10"></a>**C10 (traceable-ids)**: Every request and decision has an id that appears in logs, the `x-penfield-request` and `x-penfield-decision` headers and the UI.
- <a id="c11"></a>**C11 (fail-closed)**: An unknown caller, a target above the caller's privacy, or a model a caller may not use is a 403 (401 for the caller) with a reason, never a silent downgrade.
- <a id="c12"></a>**C12 (import-through-barrels)**: Named exports only; relative imports end in `.js`; a sibling module is imported through its `index.js`; an `index.ts` holds re-exports and no logic.
- <a id="c13"></a>**C13 (test-layout)**: Unit tests in `src/<module>/__tests__/<name>.test.ts`; fakes and shared helpers in `packages/penfield/test/helpers/`; cross-module tests in `packages/penfield/test/integration/` or `test/e2e/`; data in `test/fixtures/`; nothing else under `test/`; no `.spec.ts`.
- <a id="c14"></a>**C14 (fallow-clean)**: No unused file, export or dependency; a dependency is added in the step that first imports it; each new entry point is in `fallow.toml`'s `entry` and the package's `bin`; the placeholder `src/penfield.ts` and its test go with spec step 2.
- <a id="c15"></a>**C15 (fake-token-shape)**: Fake bearer tokens in tests and fixtures are `tok_<caller>_<hex>` and never resemble a Claude OAuth token, since the C2 rule fires in tests too.
- <a id="c16"></a>**C16 (coverage-70)**: vitest's thresholds (70 % lines, functions, branches, statements over `src/`) hold after every step.
- <a id="c17"></a>**C17 (pnpm-release-age)**: This machine's pnpm holds back packages younger than 48 h; a native build needs an `allowBuilds` entry in `pnpm-workspace.yaml`; versions are exact (`save-exact`).

## Open questions

The spec's Q3 (Stage B) and Q6 (resolved: penfield) are not carried. Q7–Q9 were this plan's and were settled at the plan pause on 2026-10-30 as D39–D41; their openers below carry the call.

- <a id="q1"></a>**Q1 (ollama-context-window)**: Ollama's `/v1` endpoints cannot set `num_ctx` per request, so how does a 64 k context reach the model? *resolved:* 2026-10-31, at item 2's stop: the loaded 35B already reports `context_length` 131072, so searle needs no change and the overlay keeps `context: 65536`
  - *plain:* A model loaded with Ollama's default context truncates long prompts silently, which looks like a bad answer rather than an error. The gateway cannot fix it on the wire without translating, which C1 forbids.
  - *lean:* Set `OLLAMA_CONTEXT_LENGTH=65536` on searle (playbook §1) and record `context` per model in the `models:` overlay so the catalogue reports it; the gateway sends nothing. Revisit when a caller needs more than 64 k.
- <a id="q2"></a>**Q2 (readiness-ping-cost)**: What does an empty-prompt `/api/generate` readiness ping cost on an MLX model, and can it evict something? *resolved:* 2026-10-31, at item 2's stop: 81 to 119 ms warm on the 35B, nothing loaded, `keep_alive: -1` untouched; `ready_prompt` stays on once [D45 (readiness-acts-on-a-hang)](#d45) lands
  - *plain:* A ping to a model that is not resident loads it, which is itself the eviction risk D14 guards against. A ping to a resident model should be cheap, but MLX models may pay a warm-up.
  - *lean:* Ping only models `/api/ps` already lists, never others; time the ping on the resident 27B and 35B at the stop. Over a second, or anything loaded that was not already resident, flips `ready_prompt` to `false` by default.
- <a id="q4"></a>**Q4 (token-estimate-quality)**: How far is chars-over-four from the node's own prompt token count for the house's traffic? *deferred:* 2026-10-31, until the log's estimate-to-count ratio is read at range 8's stop
  - *plain:* The `tokens_gt` rules route on the estimate. Code and CJK misjudge it, so a wrong estimate sends a long code prompt to the wrong profile.
  - *lean:* Log `upstream_prompt_tokens` beside the estimate (D31) and read the ratio at the Stage A review; tune thresholds in Stage C. The sample is the streams whose client sent `stream_options.include_usage` (Zed does, per step 15), since an OpenAI stream carries usage only then and [C1 (proxy-dont-translate)](#c1) keeps penfield from adding it; a stream without it logs null (confirmed at range 4's harvest).
- <a id="q5"></a>**Q5 (hint-or-downgrade-for-zed)**: When `auto` decides Claude for Zed's native agent, is `hint` or `downgrade` the better default? *deferred:* 2026-10-31, until two weeks of Zed use after range 7's stop, read from the log
  - *plain:* `hint` interrupts the flow with a message naming the model; `downgrade` answers locally and hides that the routing wanted Claude.
  - *lean:* `hint`, as the spec says; decide after the two weeks.
- <a id="q7"></a>**Q7 (sqlite-driver)**: Does plan step 2 use `node:sqlite` or `better-sqlite3`? *resolved:* 2026-10-30, `node:sqlite` behind `log/db.ts` alone, now [D39 (node-sqlite)](#d39)
  - *plain:* `node:sqlite` is built into Node 24 (verified here: `DatabaseSync` opens a db and the WAL pragma works; types are in `@types/node` 24): no native build, no `allowBuilds` entry, no compiler in the Docker image, but its API is still marked active development, so a Node minor could move a method. `better-sqlite3` is what runciter uses, stable and fast, but native: an `allowBuilds` entry, a prebuilt binary or toolchain in the Dockerfile, and the 48 h release hold.
  - *lean:* `node:sqlite`, behind `log/db.ts` alone, so a swap is one file.
- <a id="q8"></a>**Q8 (yaml-line-numbers)**: How does a zod failure report a YAML line when zod issues carry paths, not positions? *resolved:* 2026-10-30, the `yaml` package's `parseDocument` and `LineCounter`, now [D40 (yaml-line-counter)](#d40)
  - *plain:* The spec promises "a boot failure with a line number". A path like `aliases.auto.ladder` is right but slow to find in a 90-line file; a line and column is what an editor jumps to.
  - *lean:* Parse with the `yaml` package's `parseDocument` and a `LineCounter`, validate `doc.toJS()` with zod, and for each issue take `doc.getIn(issue.path, true)` as the node and `lineCounter.linePos(node.range[0])` as its line and column; an issue on a missing key reports its parent's line. The message reads `penfield.yaml:42:7 aliases.auto.ladder: <zod message>`.
- <a id="q9"></a>**Q9 (candidate-missing)**: Is a profile candidate that no discovered node has a boot failure (playbook §4) or a warning? *resolved:* 2026-10-30, static checks at load and a warning after discovery, now [D41 (candidate-two-tiers)](#d41)
  - *plain:* The spec's §5.1 fails at load on "a candidate no node could ever have"; the playbook says a candidate discovery does not find is a boot error by design. If discovery decides boot, plato cannot start while searle is down or a model is being re-pulled, which is the state D16 wants to recover from.
  - *lean:* Two tiers. At load, static facts only: an unknown key, an alias to a missing profile, a candidate naming a node that does not exist or a model a hand-listed node lacks, a pinned model a hand-listed node lacks; each fails with a line. After each discovery, a candidate no node has is a `candidate_missing` incident shown in the UI, never a boot failure. Plan step 19 corrects the playbook's line.
